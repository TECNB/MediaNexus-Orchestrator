# Frontend contract (frozen for parallel implementation)
Existing POST movie/series releases/search(/refresh) endpoints now return immediately with {query,items,comparison?}. items may initially be empty while status RUNNING. Existing recommendation endpoints wait bounded round then return {query,requested_quality,selected_quality,item,items,comparison?}; item and selected_quality may be null if no usable evaluated item. When comparison present, only COMPLETE means this round all discovered queue evaluated; PAUSED/BLOCKED cannot be treated as automatic final recommendation. User may manually choose currently RECOMMENDABLE while paused/running; choosing UNVERIFIED requires explicit risk acknowledgement. Known unsafe entries must be disabled, not acknowledged through.

comparison JSON: {id:string,status:'RUNNING'|'COMPLETE'|'PAUSED'|'BLOCKED',snapshot_at:string,checked:number,pending:number,resolve_requests:number,search_queries:number,message:string,recommended_ref:string|null}. snapshot_at ISO instant of first search snapshot (visible to user). Counts are all discovered queue evaluations, not episode counts.

Each ProwlarrRelease optional evidence: {status:'RECOMMENDABLE'|'NEEDS_PROCESSING'|'UNSUITABLE'|'UNVERIFIED',reason:string,total_bytes:number|null,target_bytes:number|null,target_files:number|null,preview:boolean,camera:boolean}. No evidence = old Prowlarr behavior. Four labels 可推荐/包含目标待处理/不适合本次目标/未核验. target_files unknown=null not 0. NEEDS_PROCESSING and UNSUITABLE disabled because current executor cannot safely organize or known conflicts. File-name quality/subtitle evidence is declaration only. Preview accepted but normal preferred.

GET /api/v1/resources/releases/comparisons/{id} -> standard Java envelope of {query,items,comparison}. POST /api/v1/resources/releases/comparisons/{id}/continue -> same; only explicit user click, no infinite auto continuation. Poll only RUNNING every ~1s with AbortSignal and stale request protection; preserve current items on transient polling failure, explain retry.

Existing create-selected payloads add optional boolean accept_unverified_risk (default false); manual raw magnet payload too but out of main frontend scope. If choosing UNVERIFIED/no evidence under a comparison require confirm('未取得文件表…仍要提交？') and send true. Choosing RECOMMENDABLE does not require risk override even if comparison not complete, but make clear manual current choice not whole queue winner. Cannot bypass NEEDS_PROCESSING/UNSUITABLE by true. Backend rechecks common safety at submission. Existing Prowlarr result without comparison must preserve behavior. Retry payloads also accept_unverified_risk if using manual unknown.
